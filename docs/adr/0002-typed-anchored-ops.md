# Replace diff-block mappings with typed, anchored ops

The delta overlay expresses every fork change as one diff block: the `-`/space lines reconstruct a locator that must occur exactly once in the upstream snapshot, and the `+`/space lines replace it. Locator and replacement are coupled, so a patch that owns a single word must carry its whole surrounding context and re-anchor it whenever upstream edits that context — and the format cannot show which part of the located text the patch owns, so "adopt upstream's new wording" and "redesign the fork" look identical (the latest sync rewrote the replacement side of six ops with no upstream cause, and nothing in the document records why). We replace it with ops built on one `anchor`: a unique span of the upstream file that gates the whole op. A `find`/`content` pair replaces text inside the anchor; an `insert` places its content at a marker inside the anchor; one anchor may carry several non-overlapping `find`/`content` pairs and at most one `insert`, all resolved against the anchor's original text and composed by position. The anchor is a hard gate — exactly one match, or the build fails and a human re-specifies it. Anchor unchanged, every edit applies automatically; anchor changed, a human decides. No three-way merge is automated; the previous `upstream/` snapshot in git is the base a human reads by hand.

## Considered Options

- **Keep the diff-block format and tighten authoring discipline.** Rejected: it leaves locator and replacement coupled, the root cause of the re-anchoring churn.
- **Automate a three-way merge from a recorded base, or keep the fork as a git branch of upstream.** Rejected: a human is wanted at every anchor change, and an automated merge would hide exactly those decisions. Hand-authored, reviewable mapping documents also keep `build.mjs` free of git and of network access.
- **Warn, rather than fail, when an anchor matches more than once.** Rejected: an ambiguous anchor can land the patch in the wrong place, and silently picking one occurrence is the mistake the gate exists to prevent.
- **One edit per op, repeating the anchor instead of grouping edits.** Rejected: several edits in one region would each need their own anchor — duplicating a wide locator, or shrinking it until it no longer covers the region the patch deliberately gates.
