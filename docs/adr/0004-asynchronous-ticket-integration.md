# Asynchronous integration with early merge release

The `/hyper-auto-coding` redesign was explicitly approved in the design discussion on 2026-10-15 (user: “确认是这个方案”), with subsequent clarifications that the merge lock covers reverse synchronization, only the initial attempt starts full integration testing, and normal child exit is assumed successful. Ticket implementations now hand their original worktree and branch to a separate, resumable integration child; the first successful merge releases dependencies, while global tests, repairs, and conflict resolution proceed asynchronously in that same integration session. The main agent schedules rather than judges acceptance, and final independent overall verification replaces the former code-review/fix/re-review gate.

## Consequences

- FIFO merge attempts hold the shared lock through forward merge, conflict abort if needed, and reverse synchronization into the original development worktree. Agent conflict handling and tests happen after release. This deliberately favors a conservative per-attempt synchronization boundary over the shorter alternative of releasing before reverse merge.
- The first attempt starts the integration child whether it merged or conflicted. The child resolves, runs global tests, repairs and commits. Subsequent attempts end on success; conflict resumes the same child rather than creating another fixer or worktree. There is no fixed conflict-retry limit or mandatory global-test rerun for later conflict rounds.
- Clean merges remain admissible after integration HEAD advances. Requiring each report to certify the latest HEAD would defeat continuous integration progress; the cost is that clean Git merges can combine changes not tested together. Complex scripts, cross-ticket verification and real-device smoke belong to the final independent gate, with fixes and fresh verification as needed.
- “Merged” releases the implementation frontier; “integrated” means the integration loop has finished and its changes have landed, not that every later branch tip is certified. Children own their acceptance; normal completion is taken at face value rather than having the main agent inspect report sufficiency. Execution faults remain faults, not fabricated successes.
- Original TDD sessions remain distinct and may run history-only retrospectives asynchronously. They do not modify the worktree after handing it to the integration child. Reports remain external until final publication, and retro delivery remains independent.

This supersedes the former serialized sync/merge/verify/manual-confirmation flow and final reviewer-driven repair cycle described in the earlier hyper-auto-coding guides. The current [English](../hyper-auto-coding.md) and [Chinese](../hyper-auto-coding.cn.md) guides describe the approved behavior; this record explains why the weaker intermediate gate is intentional.
